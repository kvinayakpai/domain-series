[In dbt, data tests are assertions you make about your models, and dbt ships with four generic ones: unique, not_null, accepted_values and relationships](https://docs.getdbt.com/docs/build/data-tests). They check that the records are well formed and agree with each other.

## What the data tests said

[Store 014's dbt project runs the 32 data tests from the series' technical companions on June's records: 31 pass](../kit/#dbt), and [the other warns that the full-cream milk book goes below zero on six days](../kit/store-014-dbt/README.md). By those tests, June was a clean month.

## What the domain tests found

[Thirteen domain tests check the same records against how a store, a warehouse and UPI work, and every one fails on June](../kit/#dbt), [as a warning that keeps its failing rows](../kit/store-014-dbt/README.md). Four of them:

- [No item goes longer without a sale than its usual rate allows while the books show stock](../kit/store-014-dbt/models/domain/silent_runs.sql): [10 rows](../kit/#dbt), the silences that mark an empty shelf.
- [Something other than the pick checks what is on each pallet](../kit/#dbt): [30 rows](../kit/#dbt), every pallet in June.
- [No count correction has a mirror image in the same building](../kit/store-014-dbt/models/domain/mirror_pairs.sql): [3 rows](../kit/#dbt), the mis-pick and the milk scan errors.
- [Every success in the provider's report has an approved payment](../kit/#dbt): [26 rows](../kit/#dbt), the extra charges.

## Why the data tests pass

[Eight of the twelve joins between June's records always agree, because one record was copied from the other](../who-saw-what/#join-the-records-two-at-a-time). A test on a copy can only pass.

A domain test joins a record to something that looks at the world: a count, a shelf audit, the payment provider's report, or the till's usual rhythm. That join is where the failures show.

## Run it

```bash
pip install dbt-duckdb
unzip store-014-dbt.zip && cd store-014-dbt
dbt build --profiles-dir .
```

[The project comes with the records and runs on DuckDB](../kit/store-014-dbt.zip). [The gap detector the retail companion runs in Python is written in SQL here, and finds the same ten silences](../kit/#dbt), and [a model called join_agreement counts how often each join agrees](../kit/store-014-dbt/models/domain/join_agreement.sql).

## Write your own

Pick one KPI your agents act on. Write down the record it reads and one observation that could contradict it, then write the test that joins them, set to warn and to keep its failing rows. [The domain layer template](../kit/domain-layer-template.yaml) has one filled-in example for each part.
